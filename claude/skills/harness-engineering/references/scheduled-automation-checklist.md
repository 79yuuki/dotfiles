# 定期自動化チェックリスト

- 固定の期間（直近24時間等）ではなく、前回の読み取り位置（カーソル/最終処理ID・日時）から読む。実行の欠落や重複で取りこぼし・二重処理が出ないため。
- 取得に失敗した source は「何も無かった」と書かず、失敗として明記する。空振りと障害を区別できるようにするため。
- 送信・投稿の直前に状態を確かめ直す（重複・既に処理済み・状況変化）。取得から送信までに状況が変わるため。
- 設定は毎回ファイルから読む。プロンプトに焼き込むと変更が反映されず古くなるため。
- 外部記事など信頼できない入力は、書き込み・送信権限を持たない読み手（サブエージェント）に読ませ、結果だけ受け取る。prompt injection で権限が悪用されないため。
