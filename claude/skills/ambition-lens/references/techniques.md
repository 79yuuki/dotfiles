## 1. 4つの軸

- **Speed**: 同じ仕事を速く。工夫は要らない。この skill では「そのまま進める」に相当する。
- **Altitude**: 抽象度を上げ、個々のタスクではなく成果を扱う。「これが終わった後、何が起きてほしい？ ゴールの先のゴールは？」
- **Depth**: 分野の第一人者のように扱う。タスクの層ではなく、一段下のデータ・道具・問題そのものに触れる。
- **Range**: 表面上必要な分野以外の知識・道具・技法も持ち込む。

## 2. Altitude

筆者は「個別のクラッシュを直して」から「アプリをクラッシュゼロに保って」へ移った。そのためにまず、クラッシュレポートを取れること、アプリのバージョンと git コミットの対応が分かること、Windows / macOS / Linux で独立に再現・検証できる環境を Claude に用意した。**Altitude を上げると、人を介さず回る durable workflow が見つかる。ただし大抵はワークフローの側を変える必要がある。**

QBR（四半期業務レビュー）資料の例。下に行くほど高い:
1. テンプレの数字を更新するのではなく、手に入るデータを全部渡して「今四半期に何が変わり、なぜで、何をすべきか教えて」
2. 「学んだことを踏まえて最も緊急な3つの意思決定を割り出し、それぞれ賛否つきで方向性の検討を始めて」
3. 「レビューの存在理由は、経営が問題を早く察知し、お金と人を正しい場所へ動かすこと。四半期資料より良いやり方を設計し、自社の過去データでそれなら早く気付けたことを示し、1四半期は現行と並走させて」

向き不向き: 本当に最終成果を求めている時に効き、創作には効きにくい。**それについて会議をするなら Altitude の好機。**「Claude、お金を稼いできて」は 2026 年時点ではまだ単独では機能しないが、上限はモデルの能力とともに上がっている。

## 3. Depth

第一人者が使う道具・技法・媒体・知識を使わせ、その人たちすら何かを学ぶところまで押す。

- **一流と同じ道具を使わせる**: 「プロとして」と頼むとモデルは語彙だけ変えて方法を変えないことが多い。markdown 表に手を伸ばしたら、データベースと統計モデルを使わせる。専門家が何を使うかはユーザーが知らなくてよい（モデルが大抵知っている）。
- **非常識な目標を置き、それは十分に妥当だと伝える**: 10秒を5秒にしたいなら 200ms を求める。無理そうに見えても、解ける問題だから続けるよう繰り返す。
- **知っていることを疑う**: 生データへのアクセスを与え、前提を敵対的に検証させる。「解約はオンボーディングの問題だと考えている。生データからそれを再現してみて」
- **新しい知識を作る**: データに深く入ったついでに盲点を探させる。「去年を再現する顧客シミュレーションをログから作り、まだ知られていない最も早い解約シグナルを見つけ、見ていないデータで予測できることを示して」
- **外部の判定者を使う**: モデルに自己採点させない。理想はモデルが自分で実行してすぐフィードバックを得られるツール。

定型プロンプト（原文）:

> I want a deeper version of this task, not a bigger one. Before rewriting it: (1) say what a top professional in this field would do here that I'm not asking for; (2) name the rawest material they would start from instead of what has already been digested for me; (3) name the specific methods and tools they would use; (4) say what, other than you or me, would show the result is right. Then rewrite my prompt to ask for exactly that.

日本語版: 「大きくではなく深くしたい。書き直す前に、(1) この分野の第一人者が、私が頼んでいないのにやること (2) 誰かが既に噛み砕いたものではなく、彼らが出発点にする最も生の素材 (3) 彼らが使う具体的な手法と道具 (4) あなたや私以外で結果が正しいと示すもの、を挙げて。そのうえで、まさにそれを頼む依頼文に書き直して」

## 4. Range

強盗映画が最初の30分で多様なメンバーを集めるのと同じ。マルチエージェント（スレッド、オーケストレーター、サブエージェント）が手軽になった今、追加の分野を持ち込ませると面白い結果が出る。最も魔法が起きやすい軸だが、ユーザー側の創造性が要る。

- **名詞を動詞に置き換える**（Tom Kelley & Jonathan Littman『The Art of Innovation』）: 四半期レビューは「資料」ではなく「忙しい人に因果の物語を信じさせ、不確実な中で30分で決めさせること」。動詞にすると、どの分野が独自の視点を持ち込めるかが見える。
- **クルーを集める**: 「この資料が最高でなければ宇宙人が地球を吹き飛ばす。人類はどんなチームを組む？」制作品質ならアナリスト・ジャーナリスト・編集者。発表するならモーション・音響デザイナー。敵対的な red team として空売り投資家とフォレンジック会計士。
- **ロールプレイの罠**: 役を演じさせると transcript が奇妙になるだけで成果は良くならない。分野と技法を見つけるために使う。「空売り屋のように書いて」ではなく「空売り屋がポジションを調べる時にやることをやって」。

## 5. 前提条件

どの軸も、ソフトウェアをインストールできるコンピュータと、関連データへのアクセス（MCP コネクタ等）を前提にする。野心案を出す時は、足りないアクセスを明示する。

## 6. 自己効力感

人は、自分にできると信じるほど実際に多くを達成する。Locke と Latham は35年分の目標設定研究から「具体的で難しい目標を与えられた人は『ベストを尽くせ』と言われた人より成果が高い」と結論した。

- できると信じる: Dantzig は未解決問題2つを宿題だと思って解いた。
- 誰かがやるのを見る: 4分の壁は Bannister の後、46日で破られた。
- 失敗してよいと許す: 『The Inner Game of Tennis』、"just a hobby" として発表された Linux。

この skill の役割は、ユーザーに「ここまで頼んでいい」と見せること。選択肢を示すこと自体が、上の「誰かがやるのを見る」に当たる。

## 7. 書き換え例（日本語の依頼）

**「来週の定例用に今月の KPI をまとめたスライド作って」**
- Altitude (Recommended): 「今月の KPI データを全部見て、何が変わり・なぜで・何をすべきかを出し、定例で決めるべき最も緊急な3つの論点を賛否つきでスライドにして」— 前提: 生の KPI データへのアクセス
- Depth: 「数字は表計算ではなく、明細から再実行できる分析スクリプトで出して。変化は要因に分解し、社内で『落ち込みは季節要因』のような説明が出ているなら、生データで再現できるか確かめてからまとめて」
- Altitude（最大）: 「定例の目的は問題を早く見つけて人とお金を動かすこと。月次スライドより早く気付ける仕組み（異常検知・週次アラート等）を設計し、過去データで早く気付けたことを示して」
- そのまま進める

**「本番で出ている NullPointerException を直して」（緊急 → 後置き）**
- まず根本原因まで直し、再現テストを通す。完了報告の末尾で同じ形式の1問:
  - Altitude (Recommended): 「本番の例外を継続的にゼロに保ちたい。例外ログの取得経路と、稼働バージョンと git コミットの対応を用意し、検知 → 再現テスト → 修正 → 検証 → PR のループを /schedule で毎日回して」— 前提: 本番ログの読み取り権限
  - Depth: 「nullness の静的解析で同じ形の NPE 候補を洗い出し、テスト付きで潰して」— 前提: ビルドに解析ツールを足す許可
  - ここで終える

**「最近チームの生産性が落ちてる気がする。どうしたらいい？」**
- Depth (Recommended): 「『落ちている気がする』を前提にせず、PR のサイクルタイム・レビュー待ち時間・デプロイ頻度を GitHub の生データから再実行できるスクリプトで計算して確かめて。本当に落ちているならどの工程で詰まっているかを特定し、打ち手の効果をどの指標で何週間後に確かめるかまで出して」— 前提: GitHub 等へのアクセス
- Altitude: 「生産性の先で起きてほしいこと（リリース速度・品質・定着）のうち、データ上いちばん悪化しているものを判定し、それを測る指標を週次で自動集計して悪化したら知らせる仕組みにして」（ユーザーに Y を聞き直さずに済むよう、データから判定させる）
- Range: 「エンジニアリングマネージャー・組織心理・待ち行列理論の各分野の人が実際にやる診断を並行で行い、結果を突き合わせて」
- そのまま相談に乗る
