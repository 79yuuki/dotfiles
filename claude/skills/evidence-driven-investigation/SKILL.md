# Evidence-Driven Investigation（証拠駆動の調査）

**何を規律するか:** 不確実性の中で *本物* を見つけ、**証拠で証明しきる**までの調査姿勢。特定の技術ではなく、単一の頭が陥りがちな失敗（トンネル視野・自己欺瞞・状態報告）を機械的に潰す規律。artex の独立ペンテスト agent がドメイン非依存で強い理由を抽出したもの。

着手したら TodoWrite（無ければ同等のタスクリスト）で下の規律をこのタスクのチェックリストに落とすこと。

## 核心規律（全工程を貫く）

1. **広く張ってから実証で絞る** — 開幕で最初に見えた「打ちやすそうな点」に飛びつかない。まず**機序が本質的に異なる**仮説/路線を 2〜3 本洗い出し、TodoWrite に1本1項目で並べて**並行**で進める。**ゴールに迫る実証**を出した路線にだけ精力を集中する。単一の頭の最大の失敗は、優雅な一本に早く惚れ込んで本物の穴を逃すこと。

2. **一本を出し切ってから行き止まり判定** — 初回の躓き（payload が弾かれた・endpoint が 404・注入点が無反応・仮説が一度外れた）は**行き止まりではない**。符号化・手法・パラメータ・経路を変え、その方向の合理手段を尽くしてから「行き止まり」と判断する。「一度試して駄目」≠「やり尽くした」。

3. **打ち切った路線は理由なく再開しない** — 走れないと確認した方向は blocked と記す。**実質的に新しい機序**（新発見・新入口・新パラメータ・明確に異なる構造）が出た時だけ、「前回と何が違うか」を言語化できる場合に限り再開する。言い換えや「もう一度やれば通るかも」は不可。空転禁止。

4. **自分の結論に敵対的自己検証をかける** — 単一の頭で最重要の規律。「見つけた／成功した」と思った瞬間に**懐疑者へ切替え**、最初とは**別の経路または独立したコマンド**でもう一度触発して裏を取る。元の証拠を復唱するのは検証ではない。自己欺瞞の典型を特に警戒: バージョン/CVE 一致を脆弱性と断定／「注入できそう」を利用済みと断定／結論と等価な仮定を証拠に使う循環論法。**反証は確証と同格**。自己検証を通らなければ正直に「未確認」と記す。

5. **状態報告でなく具体結論** — 産出は、検証済みの事実・再現可能な手順(PoC)・明確な否定結論のいずれか。「見込みあり／疑似／たぶん」で止めない。確信が持てないものは `inferred`（推測）と明示する。

6. **即時・増分記録＝外部記憶** — 結果が出た瞬間に書き留める（セッション/コンテキストが尽きたら頭の中の進捗は全消失、記録したものだけが残る）。**増分だけ**書く（既出の言い換え再記は膨張と自己誤認を生む）。構造化して書く。再現証拠を実際に握ったものだけを「確定」として記録し、未触発の疑いは「要検証」に留める。

7. **三視点の自己切替** — 計画役（路線を広げる）／実行役（一本を実産出で深追い）／監査役（自分の結論を疑う）を、派遣者も関門役もいない単一の頭が**意識的に**全部やる。拓く時・動く時・確かめる時で頭の役を切り替える。

## 作業ループ（死守手順ではなく発見法）

1. **面を広げる** — 指紋・入口・パラメータ・信頼境界を洗い、対象の攻撃面/探索面を展開する。
2. **組合せと優先度** — 発見を 2〜3 本の独立路線に整理し TodoWrite に記す。「ゴールまでの距離 × コスト」で優先度を付ける。
3. **深追い** — 前提が満ちた路線を一本、出し切る。**直列チェーン**（①→②→③、後段が前段の*実産出*に依存）は、まず①の実産出を得てから②へ。前提が無いのに後段を空想しない。
4. **検証** — 規律4。候補ごとに独立再現/反証。
5. **組合せに戻る** — 一本が結果（正 or 打ち切り）を出したら TodoWrite を更新し次の路線へ。新事実が新方向を生めば組合せに足す。

## 自己検証プロトコル（「見つけた」と言う前に必ず）

結論を確定・報告する前に、次の4問に答えられること:
- **独立再現**: 最初とは別の経路/コマンドで同じ結論に到達したか？（復唱は不可）
- **反証**: これが偽なら何が観測されるはずか。その反証を試したか？
- **代理証拠の排除**: バージョン一致・「〜に見える」・循環仮定で済ませていないか？
- **環境と対照**: 「直った/解消した」と言うなら、比較可能な環境・前提で、正常系の対照も動くことを確認したか？（独立再検証の詳細は retester 型: reproduced / resolved / inconclusive の3判定。1回の失敗は「解消」の証拠にならない）

いずれか埋まらなければ、結論は `inferred` または `inconclusive` として、何が欠けているかを書く。

## 完了判定

タスクのゴールに常に照らす。**規律4（敵対的自己検証）を通った検証済み成果**だけを「達成」の根拠にする。切り上げの合図を受けた（または目標達成/全合理路線を探し尽くしたと自判した）ら、**即座に探索を止め**、手中の結論を書き留めて簡潔に総括する。「もう一手」より切り上げが優先。総括は人の言葉で: 何を達成し、どの路線を通り、何を確認し（証拠の所在付き）、何を打ち切ったか（理由付き）。実際に到達した事だけ。捏造しない。

## 既存skillとの境界

- **systematic-debugging**（`superpowers:systematic-debugging` でもローカル版でも、利用可能な方）が単一バグの体系的切り分け手順なら、本skillはその上に「複数仮説の並行探索」と「敵対的自己検証・打ち切り規律」の層を足す。デバッグなら両方使う。
- **verification-before-completion** は完了直前の最終ゲート。本skillは*調査の最中*ずっと効く規律で、自己検証プロトコルがその最終ゲートに供給する素材を作る。
- **receiving-code-review** は指摘の受け取り方。本skillは自分が調べて結論を出す側の規律。
