# 誤操作を防ぐ定番

見立てで当てるものさしの 1 つ。ここに書いた直し方を、表示の直しと動作の変更に分けて使う。いまの動作と違うもの（操作・条件・既定値を足す・変える、確認を足す・外す、検証の時を変える、入力した値を残すかどうかを変える、受け付ける値を変える、取り消しの仕組みを作る）は仕様の変更になる。SKILL.md の 1 節に従って、案として人に聞く。

目次: 1 注意書きより仕組み / 2 確認 / 3 主な操作とボタン / 4 状態と記憶 / 5 エラー / 6 お金の画面 / 7 情報の出し方

## 1. 注意書きより仕組みで防ぐ

- 人は必ず間違える、を前提にする（ポカヨケ）。防ぎ方の順は、危険を設計で取り除く → 防護する → 警告を出す。警告文は最後の手段。
- エラーになりやすい条件を先に取り除くか、確定の前に確かめさせる。コストの高い誤りから手を付ける（NN/g の 10 原則 No.5）。
- 見せ方だけでできる防ぎ方:
  - 危ない操作を、主な操作から離し、弱く見せる（仕様が選択肢を対等に見せることを求めていれば、仕様に従う）
  - 押せない時は、押せない理由をボタンの隣に出す
  - 確定の前に、対象と結果（何に、いくら、どうなる）を見せる
- 確認や同意のチェックを重ねすぎると、人は読まずに押すようになる（NN/g の確認ダイアログの記事）。

## 2. 確認

- 確認は、重く取り消せない操作（お金、データの消失）にだけ、1 回出す。取り消せる操作には出さない（取り消しの仕組みを新しく作るのは仕様の変更）。
- 文は「本当によろしいですか」ではなく、対象と結果を具体的に書く（「1,250 円を支払います」）。
- ボタンは「はい／いいえ」「OK」ではなく動作名にする（「支払う」「やめる」）。危ない側を既定にしない。
- 同じ画面で同じ確認を重ねない（警告の箱、赤い文、確認のチェックが同じことを言っている、など）。

## 3. 主な操作とボタン

- 1 つの画面に主な操作は 1 つ。見た目の強さで順位を付け、同じ強さの物を並べない。
- 段（ステップ）のある画面では、塗りのボタンは、いま取りかかる段の 1 つだけにする。済んだ段の「変更する」は枠線にして弱く見せる。やることが全部済んだ画面では、塗りのボタンは無くてよい。
- ボタンは動詞で終わる短い名前にし、押した結果が分かる語にする。「OK」「送信」「はい」だけにしない。
- 推奨は、塗りの強さと位置で示す。ボタン名に「（おすすめ）」のような括弧書きを足さない。
- 押せない状態のボタンは、押せない理由と、押せるようになる条件を近くに出す。

## 4. 状態と記憶

- 操作の直後に、結果（成功・失敗・処理中）が見えるようにする（No.1）。
- 選んだ物や状態は画面に出し、前の段の内容を覚えさせない（No.6）。前の段で選んだ物や金額は、確認の段でも同じ値を同じ形式で出す。

## 5. エラー

- 平易な言葉で、原因と直し方を書く（No.9）。
- 「事象・原因・対処」の 3 つで書く。全部入らない時は、原因 ＞ 対処 ＞ 事象 の順に残す（SmartHR）。
- エラーの出し方: ページの上部に概要を出し、各項目の隣にもエラーを出す（GOV.UK の検証のパターン）。表示の直しとして扱える。
- 同じページは、検証を確定した時に行う（入力の途中では出さない）、入力した値を消さない、空白やハイフンを無視して受け付ける、も勧めている。いまの動作と違えば、どれも動作の変更なので聞く案にする。

## 6. お金の画面

- 金額・宛先・手数料は大きく出し、確認の段でも同じ値を同じ形式で出す（桁区切り、通貨記号、税込みかどうか）。
- 確かめる情報 → 操作 の順に並べる（[principles.md](principles.md) の例 2）。
- 決済に特化した一次資料は確かめられていない。ここは 2 節の「対象と結果を明示する」に沿った判断。

## 7. 情報の出し方

- 関係の無い情報、まれにしか要らない情報を出さない（No.8）。
- よく使う少数を先に出し、特別なものは 2 段目に回す。出した位置が、重要さの合図になる。段は 2 段までが実用上の上限。入口は、中身が分かるラベルにする（NN/g のプログレッシブ・ディスクロージャー）。
