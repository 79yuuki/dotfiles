# 日本語の書き方

プロジェクトに文体の決まり（スタイルガイド、用語集）があれば、そちらを優先する。無い時の既定がここ。言い換えは、意味を変えない時だけ行う（SKILL.md の 1 節の A）。

## 基本

- です・ます調で書く。
- 冗長な言い回しを削る。

  | 前 | 後 |
  |---|---|
  | 支払うことができます | 支払えます |
  | 削除を行う | 削除する |
  | お支払い金額となります | お支払い金額です |
  | ご確認いただけますようお願いいたします | ご確認ください |

  「〜となります」が変化を表す時（「有料となります」＝これから有料になる）は「です」にしない。意味が変わる。

- 格助詞を省かない（「残高追加」より「残高を追加する」）。
- 敬語は控えめにする。
- カタカナ語は、まず漢字語やひらがなで言えないかを考える。社内語・独自の用語は使わない。
- 同じ物は、画面・通知・エラー・ヘルプで同じ語で呼ぶ。用語集は設定ファイルにある。
- 同じ内容を、言い方を変えて繰り返さない。
- 1 文に 1 つのこと。文の長さの数値の基準は見つかっていない。まず半分にできないか試す。画面の本文の量は、SKILL.md 4 節の文字の予算（区画ごとの目安）と、[cognition.md](cognition.md) の 5 節の予算（画面全体・最初の画面）で決める。

## 部品ごと

- **見出し**: 問いの形か、その画面でやることの名前（「お支払い方法を選んでください」「支払い内容の確認」）。
- **ボタン**: 押した結果が分かる、動詞で終わる短い名前（「支払う」「残高を追加する」）。括弧書きの補足を付けない。
- **選択肢**: 選んだ後に何が起きるかが分かる名前。「はい／いいえ」で答えさせない。
- **エラー**: 事象・原因・対処。全部入らない時は 原因 ＞ 対処 ＞ 事象。
- **注記**: 本当に要る条件だけ。関係する操作のすぐ隣に、1 回だけ。

## 説明臭い言い回し

次のような言い回しは、中身を足さずに文字を増やす。消すか、短い形に替える。

| 言い回し | 直し方 |
|---|---|
| 「〜について説明します」「以下の〜をご覧ください」 | 消す。中身から始める |
| 「安心してご利用いただけます」「ぜひ〜」 | 消す。安心の根拠（何が守られるか）が要るなら、その事実だけを書く |
| 「〜することで、〜できます」 | 条件が画面の別の所（ボタン名、見出し）で示されている時だけ、結果だけにする。条件がそこにしか無いなら、条件を残して短くする（「〜すると〜できます」） |
| 「〜しましょう」の連続 | 指示は 1 つにして、操作の名前に入れる |
| 「（おすすめ）」「（〜の場合）」などの括弧書き | 見出し・配置・強さで示す |
| 同じ警告を本文と注記で 2 回 | 1 回にして、操作の隣に置く |
| 「このあと、〜があります」「〜いただくと、〜に進みます」（予告・直前の操作のなぞり） | なぞりは消す。押す前に知るべき事実は、ボタン名かボタンの下の 1 行に残す。削ると伝わる事実が減るなら B（[cognition.md](cognition.md) の 4 節） |
