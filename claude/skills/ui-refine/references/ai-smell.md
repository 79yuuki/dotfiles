# AI 感の特徴と直し方

「AI が作った感」の正体は、理由の無い装飾と、強さの順位が無いことと、説明の多さ。ここの特徴の多くはブログやコミュニティの意見で、実験の裏付けは見つかっていない。見立ての手がかりとして使い、重さは操作への影響で決める（多くは「見た目だけ」。同じ強さの物が並んで主な操作が分からないなら「迷う」）。

## 見た目

| 特徴 | 直し方 |
|---|---|
| 何でもカードに入れる。カードの中にカード | カードは、単独で操作できるまとまりだけに使う。区切りは余白と見出しで |
| 同じ強さの物が並ぶ（同じ大きさのカードが 3 枚、全部が太字、全部に色） | 強さに順位を付ける。主な物 1 つだけを強く |
| 警告の色を広い範囲に使う（区画ごと黄色や橙に塗る） | 警告の色は、危ない所そのものにだけ使う。同じ警告の繰り返しと、飾りとしての警告の色を減らす。別々の危険や状態の表示は残す |
| バッジやピル型の札が多い | 状態を伝える札だけ残し、飾りの札を消す |
| 紫から青のグラデーション、光る縁、すりガラス | 理由のある装飾だけ残す |
| 絵文字を機能のアイコンの代わりに使う | アイコンは 1 セットに揃える |
| 角丸・色・余白がばらばら、どこも同じ余白 | 体系（トークン）に揃え、余白の大小で階層を作る |
| 既定のフォントのまま、「John Doe」のような偽のデータ | 実際の文言と、ありそうな値に替える |

見た目の癖は、ui-design-system の「AI生成UIにありがちな癖」にも並んでいる。新しく見つけた癖は PR の本文に書き、どのプロジェクトにも当てはまるものは、作業の後で ui-design-system への追記を別に提案する（画面を直す作業の中で、ほかの skill を書き換えない）。

## 文（説明臭さ）

| 特徴 | 直し方 |
|---|---|
| 見出し・説明・補足・注記が重なる | 見出しと操作の名前で言えることは消す |
| 同じ警告が 2 回以上ある（区画の中と外、本文とチェックの文） | 1 回にして、関係する操作のすぐ隣に置く |
| 仕組みの説明（なぜそうなるか）が操作の前にある | 2 段目に移す。画面には、今の状態と取れる操作を出す |
| 挨拶・前置き・中身の無い安心の言葉 | 消す |
| どの部品にも説明文が付いている | 名前で分からない所だけに残す |
| 「〜することができます」「〜となります」 | [writing-ja.md](writing-ja.md) |

## 数で見る

説明文の文字数と主な操作の数を、前後で数える（[evaluation.md](evaluation.md) の 3 節）。説明が多く、主な操作が 2 つ以上ある画面から先に見る。
