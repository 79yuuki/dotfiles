# プロジェクトの設定ファイルのひな形

プロジェクトの `docs/ui-refine.md` に写して埋める。プロジェクト固有のことはここに書き、skill には書かない。鍵・パスワード・本物の個人情報は書かない（置き場所だけを書く）。

```markdown
# ui-refine の設定

ui-refine skill がこのプロジェクトの画面を直す時に読む。食い違ったら、このファイルが skill より優先する。

## 仕様の正本（変えない）

- 要件:
- 画面仕様・状態の移り変わり:
- 受入条件:
- 見せ方の決まり（文言の表、図、色、強調、並び）が書かれている所:
- E2E テストの場所と実行のコマンド:（無い時は「なし」。止まっている時は「止まっている」と理由。どちらの時も、代わりに柵にするテスト（部品のテスト、型チェック）と、撮影に使う作り物の応答の置き場所）

## 導線（1 つの PR に 1 つの導線）

| id | 名前 | 誰が | 入口の URL | 撮る状態 | テスト用のアカウント・データの置き場所 |
|---|---|---|---|---|---|
| pay | 支払う | お客さん | | 初め・確認・完了・エラー | |

## 触らない文言（直したい時は人に聞く）

無い時は「なし」と書く。空欄や「確認中」は未確認として扱い、ui-refine は文言に手を付けない。人にすぐ聞けない作業者が書く時は「確認中」とし、外部に共有した範囲を読み取った根拠（記録の場所）があれば添える。確認中のあいだの例外（範囲の外で、規約・法定の表示にも仕様が決めた文言にも当たらない A の言い換えだけ）は、SKILL.md の 0 節に従う。

### 外部に事前共有した画面の文言

| 画面 | 共有先 | 共有した日 | 共有した物の置き場所（画像・文書） |
|---|---|---|---|

### 規約・法定の表示

| 表示 | 根拠（法令・規約・契約） | 画面 |
|---|---|---|

## 法の柵（言い方の決まり）

画面の言い方・図・状態の札が越えてはいけない線。外のサービスとの関係を、利用者が知っている型（「〇〇と連携する」など）で見せる前に、ui-refine はここに照らす（skill の cognition.md の 6 節）。ui-refine が照らすのはここにある柵だけ。無い時は「なし」と書く。空欄・「確認中」の時、ui-refine は柵に関わる言い方（skill の cognition.md の 6 節 4 の観点に当たる言い方）を作らず、聞く案に回す。中身は、決める人か法務に確かめてから書く（推測で埋めない）。柵に触れる言い方は、「使える言い方」の欄からだけ選ぶ。

| 柵 | 根拠（法令・事業の形・相手先の方針） | 避ける言い方 | 使える言い方 | 確かめた人と日 |
|---|---|---|---|---|

## 外のサービス

| サービス | 流れの中でしていること | 利用者の画面はどこか（自社・相手・別のタブ） | 知っている型の候補（例: 銀行口座の連携） |
|---|---|---|---|

- 画面の縦: 2 画面分まで／最初の画面の説明文: 80 字まで／画面全体の説明文: 150 字まで（主な道の画面の既定の目安。skill の cognition.md の 5 節）
```
